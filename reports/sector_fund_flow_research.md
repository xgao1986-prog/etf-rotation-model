# 行业资金流数据调研报告

**调研时间**: 2026-06-17  
**调研目标**: 确认行业级资金流数据的可获取性，评估是否适合用于策略研究  
**重要声明**: 只做调研，不改策略

---

## 一、可用数据源调研

### 1.1 AKShare（东方财富）

| 接口 | 数据类型 | 状态 | 说明 |
|------|----------|------|------|
| `stock_sector_fund_flow_hist` | 板块历史资金流 | ⚠️ 网络不稳定 | 可获取历史日频数据，但当前网络环境502/超时 |
| `stock_sector_fund_flow_rank` | 板块资金流排名 | ✅ 可用 | 实时/今日/5日/10日排名，非历史序列 |
| `stock_concept_fund_flow_hist` | 概念历史资金流 | ⚠️ 网络不稳定 | 同上 |
| `stock_market_fund_flow` | 大盘历史资金流 | ✅ 可用 | 约100个交易日回溯 |
| `stock_individual_fund_flow` | 个股历史资金流 | ✅ 可用 | 近100个交易日，可聚合到行业 |

**关键发现**:
- AKShare的行业资金流数据**主要来自东方财富网**
- 板块历史资金流接口存在，但**网络稳定性差**（当前环境502/超时）
- 数据回溯期约为**100个交易日**（从搜索结果和接口文档推断）
- 数据频率为**日频**（日线级别）

### 1.2 东方财富网（直接）

| 数据类型 | 地址 | 状态 | 说明 |
|----------|------|------|------|
| 行业资金流实时 | https://data.eastmoney.com/bkzj/hy.html | ✅ 可用 | 可爬取实时排名数据 |
| 板块历史资金流 | https://data.eastmoney.com/bkzj/BKxxxx.html | ⚠️ 需验证 | 各板块独立页面 |

**关键发现**:
- 东方财富网提供**行业/板块/概念**三个层级的资金流数据
- 数据包括：主力净流入、超大单/大单/中单/小单净流入
- 但历史数据需要**逐日或逐板块爬取**，没有统一的历史数据API
- 需要处理反爬机制

### 1.3 申万行业资金流

| 数据源 | 状态 | 说明 |
|--------|------|------|
| 申万官方 | ❌ 未发现 | 未找到公开的行业资金流接口 |
| Wind/同花顺iFinD | ⚠️ 需付费 | 可能有，但需要商业数据授权 |
| 券商研报 | ❌ 不适用 | 非结构化数据，不适合量化 |

**结论**：
- **AKShare/东方财富**是目前唯一可获取的行业资金流数据源
- 申万官方没有公开的行业资金流历史数据接口
- 如果需要更长期的数据，可能需要**付费数据终端**（Wind、同花顺iFinD）

## 二、数据字段

### 2.1 AKShare 板块历史资金流字段（stock_sector_fund_flow_hist）

| 字段 | 类型 | 说明 | 单位 |
|------|------|------|------|
| 日期 | object | 交易日 | YYYY-MM-DD |
| 主力净流入-净额 | float64 | 主力资金净流入金额 | 元 |
| 主力净流入-净占比 | float64 | 主力资金净流入占成交额比例 | % |
| 超大单净流入-净额 | float64 | 超大单（>=100万）净流入 | 元 |
| 超大单净流入-净占比 | float64 | 超大单净流入占比 | % |
| 大单净流入-净额 | float64 | 大单（20-100万）净流入 | 元 |
| 大单净流入-净占比 | float64 | 大单净流入占比 | % |
| 中单净流入-净额 | float64 | 中单（4-20万）净流入 | 元 |
| 中单净流入-净占比 | float64 | 中单净流入占比 | % |
| 小单净流入-净额 | float64 | 小单（<4万）净流入 | 元 |
| 小单净流入-净占比 | float64 | 小单净流入占比 | % |
| 收盘价 | float64 | 板块指数收盘价 | 点 |
| 涨跌幅 | float64 | 板块指数涨跌幅 | % |

### 2.2 数据频率与回溯期

| 指标 | 数值 | 说明 |
|------|------|------|
| 数据频率 | **日频** | 每日收盘后更新 |
| 回溯期 | **约100个交易日** | 从接口文档和样本推断 |
| 历史起始于 | 约2023年中 | 推断，需验证 |
| 更新时效 | T日收盘后 | 交易日当晚或次日早盘 |

> ⚠️ **重要**：东方财富的行业资金流历史数据回溯期**有限**（约100个交易日），无法覆盖我们策略所需的2019-2026完整回测期。如果要用历史数据做回测，需要**每日定时下载并积累**。

## 三、行业分类映射问题

### 3.1 东方财富 vs 申万一级行业分类

这是**最关键的问题**。

| 维度 | 东方财富 | 申万一级 |
|------|----------|----------|
| 层级 | 二级/三级行业 | 一级行业 |
| 数量 | 约100个板块 | 31个一级 |
| 粒度 | 更细（如"半导体"） | 更粗（如"电子"） |
| 命名 | 包含"Ⅱ"等后缀 | 纯中文名称 |

### 3.2 映射关系示例

| 申万一级 | 东方财富对应板块 | 映射难度 |
|----------|----------------|----------|
| 电子(801080) | 半导体、光学光电子、元件、电子化学品Ⅱ、其他电子Ⅱ | ⚠️ 一对多，需要聚合 |
| 计算机(801750) | 计算机设备、软件开发、IT服务Ⅱ | ⚠️ 一对多，需要聚合 |
| 通信(801770) | 通信设备 | ✅ 一对一 |
| 医药生物(801150) | 医疗器械、医疗服务、医药商业、化学制药、生物制品、中药Ⅱ | ⚠️ 一对多，需要聚合 |
| 食品饮料(801120) | 白酒Ⅱ、饮料乳品、调味发酵品Ⅱ、食品加工 | ⚠️ 一对多，需要聚合 |
| 电力设备(801730) | 光伏设备、电池、电网设备、电机Ⅱ | ⚠️ 一对多，需要聚合 |
| 银行(801780) | 银行 | ✅ 一对一 |
| 非银金融(801790) | 证券Ⅱ、保险Ⅱ、多元金融 | ⚠️ 一对多，需要聚合 |

### 3.3 映射挑战

1. **一对多映射**：大多数申万一级行业需要聚合多个东方财富二级板块
2. **权重分配**：如何加权？按市值？按成分股数量？按成交额？
3. **成分股重叠**：不同板块可能有重叠成分股，简单加总会重复计算
4. **缺失板块**：部分申万一级行业可能没有直接对应的东方财富板块

### 3.4 建议映射方案

```
申万一级行业资金流 = Σ(对应东方财富二级板块资金流)

其中：
- 电子 = 半导体 + 光学光电子 + 元件 + 电子化学品Ⅱ + 其他电子Ⅱ
- 计算机 = 计算机设备 + 软件开发 + IT服务Ⅱ
- 通信 = 通信设备
- 医药生物 = 医疗器械 + 医疗服务 + 医药商业 + 化学制药 + 生物制品 + 中药Ⅱ
- ...以此类推
```

> ⚠️ **映射风险**：聚合后的资金流数据可能因重复计算而失真，需要验证成分股重叠度。

## 四、数据稳定性与可重复性

### 4.1 稳定性评估

| 维度 | 评估 | 说明 |
|------|------|------|
| 接口稳定性 | ⚠️ 差 | 当前环境频繁502/超时 |
| 数据一致性 | ✅ 较好 | 东方财富数据口径统一 |
| 反爬机制 | ⚠️ 存在 | 频繁请求可能触发限制 |
| 数据延迟 | ✅ 低 | T日收盘后当晚更新 |
| 缺失值 | ⚠️ 节假日 | 非交易日无数据，符合预期 |

### 4.2 可重复下载评估

| 维度 | 评估 | 说明 |
|------|------|------|
| 历史数据可重复 | ❌ 否 | 只能获取近期数据，无法回溯到2019 |
| 增量数据可重复 | ✅ 是 | 每日下载当日数据，可积累 |
| 数据持久化 | ⚠️ 需自建 | 需要每日存储到本地数据库 |

### 4.3 数据积累方案

如果要使用行业资金流数据，需要：

1. **每日定时下载**：设置cron任务，每日收盘后下载当日行业资金流
2. **本地存储**：存入SQLite/CSV，积累历史数据
3. **至少积累6个月**：才能开始用于回测验证
4. **长期积累**：1-2年后可用于策略回测

```
数据积累时间表：
  2026-06-17（今天）→ 开始每日下载
  2026-12-17（6个月后）→ 积累约120个交易日，可做初步验证
  2027-06-17（1年后）→ 积累约240个交易日，可做较完整验证
  2028-06-17（2年后）→ 积累约480个交易日，可用于策略回测
```

## 五、样本验证可行性评估

### 5.1 半导体、通信、医药样本验证

**当前无法完成样本验证**，原因：

1. **网络环境不稳定**：AKShare接口在当前环境频繁502/超时，无法获取数据
2. **回溯期不足**：即使能获取数据，历史数据仅约100个交易日，无法覆盖策略回测期
3. **映射复杂**：需要先将东方财富板块映射到申万一级，再做聚合计算

### 5.2 如果数据可用，验证方案设计

假设数据已成功获取并映射，验证方案如下：

**验证1：资金净流入是否领先ETF未来收益**
```
指标：
  - 板块当日主力净流入金额
  - 板块当日主力净流入率（净流入/成交额）
  - 板块当日超大单净流入金额
  
方法：
  - 计算资金指标与ETF未来1/3/5/10日收益的领先相关性
  - 比较资金流入日 vs 资金流出日的ETF后续收益
```

**验证2：连续净流入是否比单日净流入更有效**
```
指标：
  - 连续3日净流入
  - 连续5日净流入
  - 3日累计净流入/3日累计成交额
  
方法：
  - 连续净流入信号 vs 单日净流入信号
  - 比较两种信号的胜率、平均收益、最大回撤
```

**验证3：资金流入 + 扩散度是否比单独资金流入更有效**
```
指标：
  - 资金流入 + 成分股扩散度上升
  - 资金流入 + 板块涨幅 > 大盘涨幅
  - 资金流入 + 板块内上涨个股比例 > 70%
  
方法：
  - 组合信号 vs 单一资金信号
  - 比较胜率、平均收益、信息比率
```

## 六、综合结论

### 6.1 数据可用性总结

| 问题 | 结论 |
|------|------|
| 数据源是否可用？ | ✅ AKShare/东方财富有接口，但网络不稳定 |
| 数据字段是否完整？ | ✅ 主力/超大单/大单/中单/小单净流入金额和占比 |
| 能否映射到申万一级？ | ⚠️ 可以，但需聚合多个二级板块，存在一对多映射问题 |
| 数据是否稳定？ | ⚠️ 接口不稳定，但数据口径一致 |
| 回溯期是否足够？ | ❌ 否，仅约100个交易日，需要长期积累 |
| 是否适合策略研究？ | ⚠️ 当前不适合，需积累1-2年数据后才可用 |

### 6.2 关键障碍

1. **历史数据不足**：无法回溯到2019年，不能用于现有回测验证
2. **映射复杂**：东方财富二级板块与申万一级行业的映射需要大量手工工作
3. **网络不稳定**：当前环境无法稳定获取数据
4. **数据质量未知**：未验证是否有缺失、异常值、重复计算等问题

### 6.3 建议

**短期（当前）**：
- 不建议将行业资金流纳入策略
- 数据不足以支持回测验证

**中期（6-12个月后）**：
- 如果每日积累数据，6个月后可有初步样本
- 可验证资金流入与ETF收益的领先性

**长期（1-2年后）**：
- 积累足够历史数据后，可纳入策略
- 建议作为**辅助信号**（确认/增强），而非主要交易信号

### 6.4 替代方案

如果急需资金流数据，可考虑：

1. **使用个股资金流聚合**：
   - 用 `stock_individual_fund_flow` 获取ETF成分股的资金流
   - 按行业聚合成分股资金流，得到行业级资金流
   - 更灵活，但数据量更大

2. **使用付费数据终端**：
   - Wind、同花顺iFinD可能有更完整的行业资金流历史数据
   - 需要商业授权

3. **使用北向资金作为代理**：
   - `stock_hsgt_fund_flow_summary_em` 可获取北向资金历史数据
   - 北向资金在行业上的偏好变化，可作为行业轮动的间接信号
