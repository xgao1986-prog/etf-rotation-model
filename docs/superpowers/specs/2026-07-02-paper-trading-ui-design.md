# 虚拟盘图形界面设计

**日期**：2026-07-02  
**适用版本**：Paper Trading v0.3（界面接入阶段）  
**正式策略基线**：v1.2.3 / B0.4  

## 1. 目标

在现有 `app.py` 中新增独立的“虚拟盘”页签，把已经完成的虚拟账户、每日运行、订单、成交、持仓和绩效能力接入图形界面。

本阶段只做界面接入，不增加新策略，不修改 B0.4，不连接券商，也不自动执行真实交易。

## 2. 核心原则

1. 虚拟盘只使用“策略配置”页面已经保存的参数预设。
2. 创建账户后，策略参数和初始资金冻结；修改参数必须新建账户。
3. 可以同时选择多个已保存预设，建立多个独立账户并行运行。
4. 对比账户使用相同的起始日期和初始资金，保证比较公平。
5. 影子账户单独输入现金和持仓，用于模拟用户当前组合。
6. 对比账户自动模拟成交；影子账户必须由用户确认订单。
7. 影子账户未确认订单在下一个交易日自动失效，但保留完整记录。
8. 页面刷新或重复运行不得造成重复成交。

## 3. 页面位置与结构

在现有主页面增加独立的“虚拟盘”页签，与“实盘助手”并列，不合并两者职责。

虚拟盘页面包含五个区域：

### 3.1 账户总览

展示所有虚拟账户的：

- 账户名称与类型
- 使用的策略预设
- 当前总资产、现金和持仓数量
- 累计收益、年化收益、夏普率、最大回撤、Calmar
- 已完成交易胜率、月度盈利比例
- 交易次数、换手率、佣金
- 最近运行日期和账户状态

支持按账户类型、策略预设和账户状态筛选。

### 3.2 创建账户

#### 对比账户

- 一次选择一个或多个已保存策略预设。
- 手动输入统一初始资金。
- 选择统一起始日期。
- 系统为每个预设创建独立账户。
- 账户名称默认由“预设名称 + 起始日期”生成，也允许用户修改。

#### 影子账户

- 选择一个已保存策略预设。
- 手动输入实际现金。
- 导入或手动录入当前持仓。
- 创建前必须完成现金、持仓市值和总资产勾稽。

#### 创建确认

提交前展示确认清单：

- 账户名称
- 账户类型
- 策略名称及参数摘要
- 初始资金或现金与持仓
- 起始日期

同一策略、同一起始日期和同一资金的重复账户应给出警告，避免误创建。

### 3.3 今日运行

运行前展示：

- 当前日期是否为交易日
- 行情数据日期
- 评分数据日期
- 待执行信号日期
- 数据完整性检查结果

用户可以：

- 一键运行全部账户
- 只运行选中的账户

数据缺失、日期不一致或价格异常时停止对应账户运行，并明确说明原因。单个账户失败不得影响其他账户。

对比账户按模型规则自动模拟成交。所有账户重复运行同一天时，结果必须保持一致，不得重复成交。

### 3.4 待确认订单

此区域只处理影子账户订单。

每笔订单展示：

- 信号日期和建议交易日期
- ETF代码和名称
- 买卖方向
- 建议数量和参考价格
- 用户确认数量和实际价格
- 预计佣金
- 订单原因
- 当前状态

用户可以：

- 确认成交
- 修改实际成交价格和数量后确认
- 标记为未执行并填写原因
- 取消订单

确认成交后才更新现金、持仓和账户表现。

未处理订单进入下一个交易日后自动失效，状态改为 `EXPIRED`，但历史记录不得删除。

### 3.5 账户详情与策略对比

单账户详情展示：

- 当前持仓
- 历史订单
- 历史成交
- 未执行和失效记录
- 净值曲线
- 回撤曲线
- 按年和按月表现

策略对比展示：

- 多账户净值曲线
- 累计收益、年化收益、夏普率、最大回撤和 Calmar
- 已完成交易胜率、月度盈利比例
- 交易次数、换手率和佣金
- 相对 B0.4 的收益和风险差异

影子账户额外展示：

- 建议价格与实际成交价格的差异
- 建议数量与实际数量的差异
- 未执行订单数量及原因
- 实际执行结果与模型自动模拟结果的偏离

## 4. 数据与运行流程

### 4.1 策略预设

虚拟盘页面只读取现有策略预设，不提供参数编辑。账户创建时保存预设参数完整快照和校验值。

后续修改原预设不得改变已经创建的账户。

### 4.2 对比账户

1. 用户批量选择预设并输入统一资金和日期。
2. 系统创建相互独立的现金启动账户。
3. 每个交易日使用同一批行情和评分运行。
4. 交易按模型规则和开盘价自动模拟。
5. 收盘后记录持仓、现金和总资产。

### 4.3 影子账户

1. 用户选择预设并导入现金和持仓。
2. 系统生成模型建议，但不自动成交。
3. 用户确认、修改、拒绝或取消订单。
4. 只有确认成交的订单更新账户状态。
5. 未确认订单到下一个交易日自动失效。

### 4.4 订单顺序

同一批订单必须先卖后买。卖出释放的资金可以用于同一批次后续买入。现金不足、超卖、缺价和异常订单必须跳过并保留原因。

## 5. 安全边界

- 不连接券商。
- 不自动执行真实交易。
- 不修改 B0.4 策略代码、参数、ETF池或冻结数据。
- 虚拟盘使用独立数据库。
- 默认只允许停用账户，不直接删除历史。
- 删除账户或清除数据必须二次确认。
- 所有成交必须满足现金、持仓、佣金、总资产和整手约束。

## 6. 验收标准

### 6.1 功能验收

- 能从已保存预设批量创建多个对比账户。
- 初始资金可以手动输入，并统一用于批量账户。
- 能创建影子账户并导入现金和持仓。
- 能运行全部账户或选中账户。
- 对比账户能够自动模拟成交。
- 影子账户能够生成待确认订单。
- 能修改影子账户的实际价格和数量后确认成交。
- 能标记未执行、取消订单和自动失效订单。
- 能查看账户持仓、订单、成交和绩效。
- 能比较多个策略账户及 B0.4。

### 6.2 数据与安全验收

- 重复运行同一天不重复成交。
- 单个账户失败不影响其他账户。
- 创建后的账户参数不会随预设修改而变化。
- 现金、持仓市值、佣金和总资产能够勾稽。
- 订单按先卖后买执行。
- 影子账户未经确认不得改变持仓和现金。
- 原有回测、策略配置、数据管理和实盘助手页面不受影响。

### 6.3 页面验收

必须实际打开页面并完成以下流程：

1. 批量创建至少两个对比账户。
2. 创建一个影子账户并导入持仓。
3. 运行一次完整交易日。
4. 验证对比账户自动成交。
5. 分别验证影子订单确认、未执行、取消和过期。
6. 查看账户详情和多策略对比。
7. 刷新页面并重复运行，确认没有重复成交。

## 7. 本阶段不做

- 券商接口和自动下单
- 定时自动运行
- 新策略研究或参数优化
- 在虚拟盘页面修改策略参数
- 动态切换账户策略
- 多用户和权限系统
- 删除历史记录

定时自动运行和更复杂的多策略管理应在本界面稳定运行后单独立项。
